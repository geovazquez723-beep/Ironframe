# Ironframe asset factory (M04A)

Spec-driven pipeline around the Roblox Studio MCP `generate_mesh` tool. Nothing here touches the Rojo-managed
game or the Bastion; generated content lives in a **separate Studio staging place** under
`Workspace/IronframeGeneratedAssets/<batch>/`.

```
assets/specs/<batch>.json       immutable input: style, per-asset prompt/size/triangle cap/parts/intended use
assets/manifests/<batch>.json   output: status, retryCount, every attempt (ids, bbox, MeshParts, triangles, errors, evaluation)
assets/catalog/<batch>.md       generated report (tools/assetfactory.py catalog)
assets/luau/OrganizeAssets.luau run in Studio: files raw results into the hierarchy, tags, measures, anchors
assets/luau/LoadBatch001.luau   run in Studio: rebuilds staging from cloud model ids (generated by `loader`)
tools/assetfactory.py           validate | plan | record | set | catalog | loader
```

## Running a new batch
1. Copy `specs/batch_001.json` to `specs/batch_002.json`, edit assets (keep prompt + style under ~350 chars).
2. `python tools/assetfactory.py validate assets/specs/batch_002.json`
3. `python tools/assetfactory.py plan assets/specs/batch_002.json` prints the exact `generate_mesh` arguments.
4. Call `generate_mesh` with `async: true`, **at most 2 at a time**; fetch results with `wait_job_finished`.
5. Run `OrganizeAssets.luau` (edit `BATCH`/`MAP`) via `execute_luau` to file, tag and measure each model.
6. Screenshot (`screen_capture` with `camera_position`/`look_at_position`), judge, then `record` an attempt JSON
   per asset and `set --persistence` after verifying the cloud model loads. `catalog` and `loader` regenerate outputs.

## What the platform actually does (observed, batch_001)
- `generate_mesh` args: `textPrompt`, `size{x,y,z}`, `maxTriangles` (12-20000), `segmentation` (auto|none|explicit),
  `partNames` (max 8), `async`. Output: a Model of `*_geom` MeshParts with baked texture (no SurfaceAppearance),
  attributes `RBX_AI_GENERATED/_ID/_TYPE`, parts **unanchored**. The job result returns `generationId`
  and `publishedAssetId` (the model is saved as an asset on the account - confirm its visibility is private).
- The triangle cap was respected on every result (<= cap). `size` is a *fit* hint: results were usually smaller than
  requested and sometimes differently proportioned, so verify bbox instead of trusting the request.
- Triangle counts are not shown by Studio directly; `OrganizeAssets.luau` reads them from the mesh asset
  (`AssetService:CreateEditableMeshAsync(...):GetFaces()`), which worked for these owner assets.
- Prompt > ~560 chars failed ("Character limit exceeded"). 3 concurrent jobs gave one `Too Many Requests`
  at the publish step; the same prompt succeeded on one later retry. `wait_job_finished` and `screen_capture` often
  time out while jobs run, though the results still arrive (poll the Workspace).
- `GenerationService:GenerateModelAsync`, `GenerateMeshAsync` and `LoadGeneratedMeshAsync` exist in this Studio but
  were **not exercised**: the MCP tool already provides the supported path, including async jobs.
- Prompts naming a worn object ("shoulder armor") can yield wearable human armor; describe a *machine part* and
  say what it is not. Both MEC_001 attempts failed this way.

## Persistence status (verified, not assumed)
- **Cloud models: verified.** For 7 of 8 assets `InsertService:LoadAsset(modelAssetId)` returns the model with every
  staged MeshId present, and the loader snippet round-tripped all seven. IDs are in the manifest.
- **Place file: NOT saved.** Staging lives in an unsaved Place1 (PlaceId 0); the tools expose no save. Minimum manual
  step: in that Studio window use File > Save to File As and keep the `.rbxl` outside the repo (or File > Save to Roblox).
- **Git:** only ids, metrics and snippets are in the repo, not binary meshes. Rebuild with `LoadBatch001.luau`.
- Visual acceptance is **not** rig compatibility: pivots are arbitrary, left/right are not mirrored, and mesh origin
  conventions differ from `ASSET_PIPELINE.md` (a re-pivot step is needed before PartKit overrides).

## Recommended for batch 002
Use 2 concurrent jobs; make the first step a size check (generated bbox ran 40-65% of requested); regenerate
MEC_001 as a single-part pauldron or with `generate_procedural_model`; ask for taller proportions on the crane hook and
tool cabinet; consider `partNames` that match PartKit part names (e.g. `PauldronShell`) to ease replacement.
